## 1. P0（必须先修）

### P0-1 `auto_correct` 默认开启，静默误删合法「单音节动词重叠」与「时/餐 量词重叠」【已实跑复现】

- **证据**：`analysis.py:415-419`（`_repeat_candidate` 的 `len(block)==1` 分支）+ `analysis.py:92-97`（`_QUANTIFIER_CLASSIFIERS`）+ `pipeline.py:342-356`（`_auto_correct` 重复阶段）。
  ```python
  if len(block) == 1:
      if cross_word:
          return True   # 老老师 路径：无任何动词保护
  ```
- **根因（两处）**：
  1. `cleanup.py:30-35` 有 `_PREFIX_VERB_KEEP`（理唱游放过握…用出打抬吹…）保护单音节动词重叠，但 **`analysis` 完全没有对应集合**（实测 `hasattr(analysis, "_PREFIX_VERB_KEEP") == False`）。`cross_word=True` 直接判口吃。
  2. **超集不变量已破**：`analysis.py:90` 注释要求「Keep this a superset of cleanup._MEASURE_CHARS」，实测 `cleanup._MEASURE_CHARS - analysis._QUANTIFIER_CLASSIFIERS = {时, 餐}`。
- **净效果**：pipeline 先跑 `cleanup.clean_sentences`（保住文本），`run()` 再跑 `_auto_correct`（`analysis.find_repeats` 重新判口吃 → `edit.apply_repeat` 折叠）。cleanup 的保护被 analysis 绕过，**删字永久写入 transcript → 进所有导出**。`auto_correct` 新任务默认 `true`（`config.py` / SPEC §3.1），用户无感知。
- **实跑复现**（`_scratch/2026-11-19/repro_autocorrect.py`，cleanup→find_repeats→apply_repeat 全链路）：
  ```
  理理发   | cleanup后=理理发   | repeat issues=1 | auto_correct后=理发    <-- 误删!
  打打电话 | cleanup后=打打电话 | repeat issues=1 | auto_correct后=打电话  <-- 误删!
  用用心   | cleanup后=用用心   | repeat issues=1 | auto_correct后=用心    <-- 误删!
  一餐一餐 | cleanup后=一餐一餐 | repeat issues=1 | auto_correct后=一餐    <-- 误删!
  一时一时 | cleanup后=一时一时 | repeat issues=1 | auto_correct后=一时    <-- 误删!
  老老师   | cleanup后=老师     | repeat issues=0 | auto_correct后=老师    （正确口吃，仍清）
  一个一个 | cleanup后=一个一个 | repeat issues=0 | auto_correct后=一个一个（正确保护）
  看看/琢磨琢磨 | 不变 | issues=0                                          （正确保护）
  ```
- **与历史审计的关系**：这是 2026-11-18「known#4 量词/ABAB 表双份」的**恶化新变体**——上轮只修了 `cleanup` 并声称「analysis 超集对齐」，但 `analysis` 的 `cross_word` 动词保护从未补、超集对 `时/餐` 实际已破。回归测试只测 `cleanup.collapse_stutters`（`test_audit_2026_11_18_text.py:170`），**未测 `find_repeats`/`_auto_correct`** → 漏网（见 §6）。
- **最小修复**：把 `_PREFIX_VERB_KEEP` 与量词表提升到 `textutil` 单一真源；`_repeat_candidate` 的 `cross_word` 分支先查动词保护（`block in _PREFIX_VERB_KEEP → False`）；`analysis._QUANTIFIER_CLASSIFIERS |= cleanup._MEASURE_CHARS`（或直接共享）。补「auto_correct 后 理理发/打打电话/一餐一餐 不变」回归。

### P0-2 交付目录已含 188MB 运行期用户数据；重构建无备份直接销毁【已实测】

- **证据**：`#release/声迹_portable/data/` 实测含 `transcripts/` **69 份**、`voicetrace.db`（77KB）+ `voicetrace.db-wal`（**4.1MB**）+ `-shm`、`settings.json`、`logs/`、`thumbs/`、`cache/`、`partial/`、`webview/`、`window-state.json`（另有嵌套 `data/data/`）。`SHA256SUMS.txt` 共 20847 行，**运行期 `data/` 命中 0**（965 个 `data/` 匹配全是 `engine/third_party/.../data/` 源码目录）。
- **成因**：SPEC §6 验收要求双击包内 exe；`run-perf.cmd:220-227` 也直接在交付目录 `Start-Process $exePath`，其 `finally`（`:255-259`）只杀进程、**从不清理 `$release\data`**。验收/性能测试把用户数据写进了交付目录。
- **两个后果**：
  1. **隐私**：当前目录直接压缩分发即泄露 69 份用户转录 + 数据库 + 日志。`build-release.ps1:612-616` 第 14 项「包内不含运行期 data\」→ **当前包 `-Verify` 必失败**。
  2. **销毁**：`build-release.ps1:807-812` 重构建时 `Remove-Tree $dataDir` **无备份**，违反工作区硬约束「删除可回滚」（根 AGENTS §3）；`:917` 仍打印「打包完成」，无「验收后 data 会回流」提示。
- **澄清**：构建脚本本身**会**在重构建时清掉 data（`:807-812`），所以「 freshly rebuilt 」的包是干净的；危险在于**当前交付目录是脏的**，且**重建销毁唯一副本无备份**。
- **最小修复**：出货前独立清理步骤（或 `-Ship` 开关，清理后才算可交付）；删 `data` 前备份到 `_archive/<日期>-release-data/`；`run-perf` 改用隔离副本或独立 `--data-dir`；构建结尾强制提示「验收产生的 data 不进包」。

## 2. P1（高危）

### P1-1 失败的重试让旧字幕（含用户编辑）在 UI 不可访问【跨层已核实】

- **证据**：`server.py:476-479`（`retry_job` 重置 `has_transcript=0, issues_json=None`，**但不删 transcript 文件**）；前端全按 `has_transcript` 门禁：`store.tsx:634`（WS done 事件）、`:674`（重连补齐）、`:741`（`selectJob`）。
- **触发**：一个 `done` 且用户编辑过的任务 → 点「重试」→ `has_transcript=0` → 重试**再失败**（`status=error`，`pipeline.py:312/329` 不恢复 `has_transcript`）→ 旧 transcript 文件仍在盘（含编辑），但 UI 因 `has_transcript=0` 拒绝加载，`Shell.tsx:132` 只显示错误页。
- **后果**：用户编辑过的字幕**数据仍在盘但 UI 丢失访问**（可恢复：再次重试成功，或手工取 `data/transcripts/<id>.json`）。
- **最小修复**：`retry_job` 不要清 `has_transcript`（让旧稿在新稿落盘前仍可访问；pipeline 终稿会置 1）；或错误路径按文件存在恢复 `has_transcript`。

### P1-2 `edit` 重对齐把英文撇号/连字符词从中间切开【已实跑复现，违 SPEC §3.2】

- **证据**：`edit.py:139-154`（重对齐用严格 `new_positions[j]==new_positions[j-1]+1` 判相邻，`'`/`-` 被 `content_positions` 当标点剔除 → 位置不连续 → 切词）。
- **实跑**（`_scratch/2026-11-19/repro_text.py`）：
  ```
  edit.set_sentence_text 后 words: ['I', 'don', 't', 'know', 'well', 'known']
  segmentation  后 words: ['I', "don't", 'know', 'well-known']
  ```
- **后果**：任何含 `don't / well-known` 的句子被编辑（`set_sentence_text`/`apply_replace`）后 words 形状错 → JSON / ASS karaoke 导出错。与 `segmentation` 的正确分词分叉。
- **最小修复**：复用 `segmentation._inside_word`/`_WORD_JOINERS`（允许间隙全为 `'’-`）判词边界，而非严格 `pos+1`。

### P1-3 模型预检/校验只数「目录非空」，半成品包可出厂

- **证据**：`build-release.ps1:355-360`（预检）与 `:537-545`（Verify）均只判 `文件数 > 0`。必需文件：`runtime.py:217` 选 `models/vad/VAD/cmvn.ark`；`third_party/.../asr.py:53`、`fireredpunc/punc.py`、`fireredvad` 读 `model.pth.tar`；aed 需 `model.pth.tar`(4.7GB)/`cmvn.ark`/`dict.txt`/`train_bpe1000.model`。
- **触发**：HF 下载中断（`download_models.py:58-64` 只打印 `dir_size`，无完整性断言），aed 仅剩 README/`.cache` 也算「非空」→ 包出厂后**首次转录才炸**。
- **最小修复**：预检与 Verify 改按白名单断言文件存在 + 最小字节数（含 `vad/VAD/`）。

### P1-4 便携 Python 与 site-packages 的 ABI 版本不校验

- **证据**：`build-release.ps1:126-133` 接受任意 `-PythonRuntime`；`:565` 只匹配 `Python 3\.\d+`；`:587` 用 `find_spec('torch')`（不加载、不验 ABI）。`.venv/pyvenv.cfg` = 3.11，`torch-2.1.0+cu118`（cp311）。
- **触发**：传入 3.12/3.13 运行时 → 全部 Verify 项 PASS，实际 `import torch` 必失败。
- **与 known#6（D6）相邻但不同**：这是廉价的版本匹配断言，不需真 import。
- **最小修复**：预检断言 runtime 与 venv 的 `sys.version_info[:2]` 相等且为 (3,11)。

### P1-5 `-SkipPayload` 重写使用说明但不重算清单，仍 exit 0 报成功

- **证据**：`build-release.ps1:883-890` 无条件写 `使用说明.txt`；`:892-905` 跳过 `Write-Checksums`/`Invoke-Verify`；`:917-918` `exit 0` + 「打包完成」。
- **后果**：旧 `SHA256SUMS.txt` 与新 readme 哈希必然不符 → 下次 `-Verify` 第 13 项失败；payload 不拷、data 不清，脚本却报绿。（三 `-Skip` 全给的 exit 2 路径 `:731-738` 是对的；问题在**单独** `-SkipPayload`。）
- **最小修复**：`-SkipPayload` 时同时跳过 readme 写入，或末尾非 0 退出并标注「非完整包」。

### P1-6 编辑草稿在切任务/返回/刷新时静默丢失【已核实】

- **证据**：`Shell.tsx:139` `<TaskEditor key={selectedJob.id}>`（切任务即重挂载）；`TaskEditor.tsx:121` `draftDirty` 存在但只用于 `:283`/`:419`（导出守卫/页脚），**无切走/卸载守卫**；全仓 `beforeunload` **0 命中**。
- **触发**：编辑条有未保存草稿时点其它任务/返回/刷新 → key 变化重挂载，`draft` 本地态清零，无确认。
- **最小修复**：切走/卸载前若 `draftDirty` 弹 confirm，或加 `beforeunload` 提示。

### P1-7 mock 与 SPEC §3 行为漂移，掩盖三类真问题（dev-only）

- **证据**（`frontend/mock/server.mjs`，两路子审计一致）：
  - settings 仅 **14 项**，缺 `vad_max_speech_ms`/`subtitle_clean_stutter`/`subtitle_merge_gap_ms`/`reduce_motion`/`gpu_memory_fraction`/`vram_headroom_mb`（后两项引擎 `config.py:47-48` 确有）→ 设置页 6 控件在 mock 下恒 undefined；PUT 无上下限钳制、无 `"false"` 解析（SPEC:169-170）。
  - `PUT /sentences`/`apply`/`undo`（`:736/754/799`）**完全忽略 `expected_version`**，无 CAS/409（SPEC:81-82）→ 并发写冲突分支永不被演练。
  - `export`（`:817-834`）无绝对路径/扩展名/保留名/原子写/同名序号，`fsp.writeFile` **直接覆盖**（SPEC:83-85）；非法 format 静默降级 srt。
  - 另：`:609-617` PUT 按平铺取 body，但 `engine.ts:577` 发 `{settings:{…}}` 信封 → 无键命中，返回旧值前端却 toast「已保存」。
- **后果**：`pnpm dev:mock` 下设置保存、409 冲突、导出覆盖三类路径无法验证，真问题被掩盖。
- **最小修复**：mock 解 `body.settings`、补 20 项 + 钳制、实现 CAS 与 export 校验；或在 mock 头部显式标注「不校验」清单。
